# 个人版精简执行指导

> 文档日期：2026-09-02
> 最近更新：2026-09-02
>
> 本文记录个人版精简的边界、已经完成的工作和后续执行顺序。协议转换核心暂不修改。

## 1. 目标

本项目用于个人部署，将多个上游 AI 渠道聚合为一个统一的大模型服务入口。精简目标是移除个人使用不需要的平台运营能力，降低维护范围，同时保留请求转发、协议转换、任务能力、节点能力和诊断能力。

个人模式不是“关闭所有计费逻辑”，而是：

- 不提供充值、支付、订阅和运营奖励；
- 仍然保留管理员额度、Token 额度、预扣、结算、退款和用量记录；
- 仍然保留渠道选择、失败重试、模型映射和协议转换；
- 仍然保留任务链路、多节点和系统任务；
- 不因精简运营模块而降低安全校验、权限控制或日志能力。

## 2. 本阶段边界

### 2.1 本阶段只处理

- 充值、支付及支付渠道；
- Stripe、Creem、易支付、Waffo、Waffo Pancake；
- 订阅套餐、订阅购买、订阅重置和订阅预扣；
- 兑换码；
- 签到奖励；
- 邀请、推广和分成；
- 公开价格页；
- 排行榜；
- 与上述功能直接绑定的设置、路由、模型、服务、前端页面、静态资源、依赖和旧数据清理。

### 2.2 明确保留

以下能力不能因本阶段精简而删除或隐藏：

- 任务插件、视频任务、Suno、Midjourney；
- 任务提交、任务轮询、任务结果和任务产物代理；
- `/v1/tasks`、视频、Midjourney 和任务插件相关路由；
- `Task`、`TaskPlugin`、`Midjourney` 数据表；
- 任务计费和任务用量记账；
- io.net 部署、多节点部署和节点状态上报；
- `SystemInstance`、多节点管理接口；
- `SystemTask`、`SystemTaskLock` 及系统任务处理器；
- Casbin/Authz、渠道权限和任务插件权限；
- 普通同步中继、协议转换、图片、音频、Embedding、Rerank；
- `PerfMetric`、`QuotaData`、请求日志、用量日志、渠道测试和模型更新；
- Codex 等上游渠道的 OAuth 凭证和刷新链路。

本阶段不修改 `relay/`、`relaykit/` 的协议转换器实现和公共 API，不修改受保护的项目名称、作者、版权、许可证和归属信息。

## 3. 已完成的第一阶段工作

### 3.1 后端平台运营模块

已经移除：

- 充值和支付 Controller；
- Stripe、Creem、易支付、Waffo、Waffo Pancake 实现；
- 支付回调、支付合规确认和返回地址逻辑；
- 订阅 Controller、订阅支付和订阅重置任务；
- 兑换码、签到和排行榜 Controller、Service、Model；
- 与这些功能专用的测试、设置和常量。

同时清理了用户模型中的平台运营字段：

```text
StripeCustomer
AffCode
AffCount
AffQuota
AffHistoryQuota
InviterId
```

`User.Email`、管理员账户、Token、额度、日志和权限字段继续保留。

### 3.2 计费边界

个人版请求和任务统一使用管理员用户的钱包额度作为资金来源：

```text
请求/任务
  → 预估额度
  → 预扣管理员钱包额度
  → 预扣 Token 额度
  → 上游请求或任务提交
  → 实际用量结算，或异常退款
```

已经完成：

- 删除订阅资金来源和订阅结算分支；
- `NewBillingSession` 固定使用 `WalletFunding`；
- 普通请求和任务差额结算固定调整管理员钱包；
- 保留 Token 额度预扣、补扣、差额退回和退款；
- 保留 `UsageAccounting` 窄接口和 `BillingSettler` 的任务/追加预扣能力；
- 清理 `RelayInfo` 中不再使用的订阅记账字段；
- 保留 quota saturation、NaN、Inf、负数和溢出保护。

钱包额度在这里表示内部额度账户，不表示重新开放充值页面。

### 3.3 前端入口

已经移除：

- 钱包、充值、订阅、兑换码、排行榜和公开价格页；
- 充值、支付、订阅和签到设置区；
- 充值分组倍率配置；
- 充值日志筛选和支付审计详情；
- 支付品牌静态资源和未使用的 Stripe 图标；
- 相关旧页面路由和旧运营入口跳转。

保留：

- 任务插件、视频任务、Suno、Midjourney；
- 任务日志、任务产物、多节点和部署管理；
- 普通模型定价、任务定价、日志和性能诊断；
- Codex 渠道配置及上游凭证管理。

前端保留的用户可见文案继续通过 i18n 管理；已删除入口不再注册对应组件和路由。

### 4.5 迁移实现要求

迁移函数 `cleanupRemovedPersonalSchema` 具备以下行为：

- 删除前使用 `HasTable`、`HasColumn` 检查存在性；
- 删除表不使用 `CASCADE`；
- 删除用户字段使用方言安全的标识符；
- SQLite 删除字段前清理关联旧索引；原生删除字段失败时回退到 GORM 表重建；
- 删除配置时按当前数据库方言引用 `key` 保留字列名；
- 迁移重复执行不会报错，也不会重复删除核心数据；
- `AutoMigrate` 的模型清单不包含已删除运营表。

## 6. 后续执行顺序

### 第二阶段：只保留管理员密码登录

本阶段已完成：

- 个人模式固定使用唯一管理员所有者，登录请求中的用户名仅为兼容字段；
- 删除用户 OAuth 登录和绑定、Passkey、2FA、邮箱验证、密码找回和自定义用户 OAuth；
- 删除对应后端路由、前端入口、模型、配置和 Go 依赖；
- 渠道凭证 OAuth（包括 Codex 刷新）继续保留；
- 渠道密钥查看改为管理员密码安全证明，证明绑定当前管理员 Session、鉴权版本和 `channel.key.read` 作用域。

普通用户历史数据和已有 API Token 不主动删除；个人模式不再提供普通用户面板登录、注册和身份绑定入口。

### 第三阶段：数据库认证结构清理

本阶段已完成认证扩展表、用户身份字段和旧认证配置的幂等清理。新数据库不会创建这些认证扩展表；旧数据库启动时按依赖顺序删除表和字段，不使用 `CASCADE`，也不会删除用户、Token、日志、任务、节点和统计数据。

### 第四阶段：固定个人模式与单管理员运行时收口

本阶段目标是让运行时不再依赖个人模式开关，也不再提供普通用户认证和用户管理入口：

- `CurrentMode()` 固定返回 `personal`，旧的外部模式、演示模式分支和模式切换入口不再保留；
- 初始化固定创建唯一 `root` 管理员，旧请求中的用户名和模式字段仅兼容接收；
- 普通用户历史记录、Token 和 `user_id` 关联继续保留，但不再进入面板或 Relay 鉴权链路；
- 任务插件、视频任务、Suno、Midjourney、任务轮询、任务产物、多节点和系统任务继续保留；
- 清理插件路由保留名单中的注册、OAuth、密码找回、OTP、充值、订阅、兑换码、钱包、价格和排行榜命名空间；
- OpenAPI 文档删除已不存在的注册、身份扩展、用户管理和支付运营接口，保留仍在文档中的管理员登录、Session、Token、任务、渠道和统计接口。

本阶段已完成：

- 个人模式和管理员所有者请求链路已固定，启动阶段即校验管理员歧义；
- 用户管理后端路由、孤立 Controller/Service/Model 代码已移除；
- 前端用户详情失效请求、用户管理权限编辑器残留和首页多用户宣传已清理；
- 分组计价不再错误依赖已关闭的 `user_management` 能力；
- 初始化向导只维护密码和确认密码，新前端不再主动提交旧模式配置字段；
- OpenAPI、插件路由保留名单和管理员认证文档已同步；
- `go test`、`relaykit` 构建、前端类型检查、测试、构建和 i18n 同步均已通过。

旧用户、Token、日志、任务和统计数据仍保留；普通用户记录只作为历史数据存在，不再进入运行时认证链路。

### 第五阶段：协议转换回归矩阵（下一阶段）

```text
现有协议入口
  → 请求格式 × 上游渠道 × 流式/非流式 × Usage/错误终态
  → 建立最小可复现回归用例
  → 定位协议转换差异
  → 在不破坏 relaykit 公共 API 的前提下修复
```

协议转换核心在本阶段仍未修改；后续工作必须先建立覆盖矩阵，再针对明确失败用例进行最小修复。

## 7. 禁止事项

- 不删除任务插件、视频、Suno、Midjourney 和任务产物代理；
- 不删除 io.net、部署、多节点、节点状态和系统任务；
- 不删除 Casbin/Authz、渠道权限和任务插件权限；
- 不删除普通图片、音频、Embedding、Rerank 和 Codex 渠道能力；
- 不修改 `relay/`、`relaykit/` 的转换器实现和公共转换 API；
- 不通过前端隐藏代替后端路由保护；
- 不为了删除支付而删除管理员额度、Token 额度、预扣、结算、退款和日志；
- 不修改项目名称、作者、版权、许可证和归属信息。
