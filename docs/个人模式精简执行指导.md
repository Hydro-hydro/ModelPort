# 个人版精简执行指导

> 文档日期：2026-09-02
> 最近更新：2026-09-03
>
> 本文记录个人版精简的边界、已经完成的工作和后续执行顺序。协议转换核心暂不修改。

## 1. 目标

本项目用于个人部署，将多个上游 AI 渠道聚合为一个统一的大模型服务入口。精简目标是移除个人使用不需要的平台运营能力，降低维护范围，同时保留请求转发、协议转换、任务能力、节点能力和诊断能力。

个人模式不是“关闭所有计费逻辑”，而是：

- 不提供充值、支付、订阅和运营奖励；
- 仍然保留管理员额度、Token 额度、预扣、结算、退款和用量记录；
- 仍然保留渠道选择、失败重试、模型映射和协议转换；
- 仍然保留任务链路、多节点和系统任务；
- 不因精简运营模块而降低安全校验、权限控制或日志能力。

## 2. 本阶段边界

### 2.1 本阶段只处理

- 充值、支付及支付渠道；
- Stripe、Creem、易支付、Waffo、Waffo Pancake；
- 订阅套餐、订阅购买、订阅重置和订阅预扣；
- 兑换码；
- 签到奖励；
- 邀请、推广和分成；
- 面向访客的公开商业价格页（模型广场和内部模型价格接口保留）；
- 排行榜；
- 与上述功能直接绑定的设置、路由、模型、服务、前端页面、静态资源、依赖和旧数据清理。

### 2.2 明确保留

以下能力不能因本阶段精简而删除或隐藏：

- 任务插件、视频任务、Suno、Midjourney；
- 任务提交、任务轮询、任务结果和任务产物代理；
- `/v1/tasks`、视频、Midjourney 和任务插件相关路由；
- `Task`、`TaskPlugin`、`Midjourney` 数据表；
- 任务计费和任务用量记账；
- io.net 部署、多节点部署和节点状态上报；
- `SystemInstance`、多节点管理接口；
- `SystemTask`、`SystemTaskLock` 及系统任务处理器；
- Casbin/Authz、渠道权限和任务插件权限；
- 普通同步中继、协议转换、图片、音频、Embedding、Rerank；
- `PerfMetric`、`QuotaData`、请求日志、用量日志、渠道测试和模型更新；
- Codex 等上游渠道的 OAuth 凭证和刷新链路。

本阶段不修改 `relay/`、`relaykit/` 的协议转换器实现和公共 API，不修改受保护的项目名称、作者、版权、许可证和归属信息。

## 3. 已完成的第一阶段工作

### 3.1 后端平台运营模块

已经移除：

- 充值和支付 Controller；
- Stripe、Creem、易支付、Waffo、Waffo Pancake 实现；
- 支付回调、支付合规确认和返回地址逻辑；
- 订阅 Controller、订阅支付和订阅重置任务；
- 兑换码、签到和排行榜 Controller、Service、Model；
- 与这些功能专用的测试、设置和常量。

同时清理了用户模型中的平台运营字段：

```text
StripeCustomer
AffCode
AffCount
AffQuota
AffHistoryQuota
InviterId
```

`User.Email`、管理员账户、Token、额度、日志和权限字段继续保留。

### 3.2 计费边界

个人版请求和任务统一使用管理员用户的钱包额度作为资金来源：

```text
请求/任务
  → 预估额度
  → 预扣管理员钱包额度
  → 预扣 Token 额度
  → 上游请求或任务提交
  → 实际用量结算，或异常退款
```

已经完成：

- 删除订阅资金来源和订阅结算分支；
- `NewBillingSession` 固定使用 `WalletFunding`；
- 普通请求和任务差额结算固定调整管理员钱包；
- 保留 Token 额度预扣、补扣、差额退回和退款；
- 保留 `UsageAccounting` 窄接口和 `BillingSettler` 的任务/追加预扣能力；
- 清理 `RelayInfo` 中不再使用的订阅记账字段；
- 保留 quota saturation、NaN、Inf、负数和溢出保护。

钱包额度在这里表示内部额度账户，不表示重新开放充值页面。

### 3.3 前端入口

已经移除：

- 钱包、充值、订阅、兑换码、排行榜和面向访客的公开商业价格页；
- 充值、支付、订阅和签到设置区；
- 充值分组倍率配置；
- 充值日志筛选和支付审计详情；
- 支付品牌静态资源和未使用的 Stripe 图标；
- 相关旧页面路由和旧运营入口跳转。

保留：

- 任务插件、视频任务、Suno、Midjourney；
- 任务日志、任务产物、多节点和部署管理；
- 模型广场、模型目录、模型价格、任务定价、日志和性能诊断；
- Codex 渠道配置及上游凭证管理。

前端保留的用户可见文案继续通过 i18n 管理；已删除入口不再注册对应组件和路由。

### 4.5 迁移实现要求

迁移函数 `cleanupRemovedPersonalSchema` 具备以下行为：

- 删除前使用 `HasTable`、`HasColumn` 检查存在性；
- 删除表不使用 `CASCADE`；
- 删除用户字段使用方言安全的标识符；
- SQLite 删除字段前清理关联旧索引；原生删除字段失败时回退到 GORM 表重建；
- 删除配置时按当前数据库方言引用 `key` 保留字列名；
- 迁移重复执行不会报错，也不会重复删除核心数据；
- `AutoMigrate` 的模型清单不包含已删除运营表。

## 6. 当前状态与后续执行顺序

### 6.1 单管理员和数据库收口

以下工作已经完成：

- 个人模式固定使用唯一 root 管理员，初始化时忽略用户名和旧模式字段；
- 管理员登录、Session、JWT、API Token 和渠道密钥密码安全证明已收口；
- 用户 OAuth、Passkey、2FA、邮箱验证、密码找回和用户管理入口已移除；
- 认证扩展表、运营表、第三方身份字段和废弃配置已完成幂等清理；
- 普通用户历史数据、Token、日志、任务和统计关联不删除，但不再进入运行时认证链路。

### 6.2 模型广场、模型价格和路由分组

本阶段已完成并保留以下能力：

- 恢复 `GET /api/pricing`，仅允许 root 管理员访问；
- 模型广场继续展示模型价格、厂商、支持的接口类型、路由分组倍率和自动分组；
- `ModelPrice`、`ModelRatio`、分组倍率、动态计费、任务价格、模型同步和价格同步继续保留；
- 删除账户用户组权限和特殊可用分组配置，`GroupRatio`、`GroupGroupRatio`、`AutoGroups`、Token 自动分组和跨分组重试继续保留；
- root 管理员默认可以使用所有已配置路由分组，Token 指定分组仍限制当前请求范围；
- `UserUsableGroups` 和 `GroupSpecialUsableGroup` 旧配置仅在启动时幂等清理，不再参与运行时判断；
- 模型、渠道、Playground、Token 和价格接口统一使用“路由分组”语义。

### 6.3 系统信息和系统公告后端链路

本阶段已完成后端收口：

- `GetStatus` 不再返回页脚、系统公告、用户协议和隐私政策相关字段；
- `/api/notice`、`/api/about`、`/api/user-agreement`、`/api/privacy-policy` 和 `/api/home_page_content` 不再注册；
- 删除 `Notice`、`About`、`HomePageContent`、`Footer` 和系统公告配置入口；
- 旧库中的上述配置以及 `console_setting.announcements`、`legal.*` 配置启动时幂等清理；
- 旧客户端重新提交已删除配置时忽略，不会重新写入配置表或运行时配置；
- API 信息、FAQ 和 Uptime Kuma 状态链路不在本阶段删除。

### 6.5 下一阶段：协议转换回归矩阵

```text
模型广场与路由分组稳定
  → 建立请求格式 × 上游渠道 × 流式/非流式 × Usage/错误终态矩阵
  → 为每个已知问题建立最小可复现用例
  → 定位协议转换差异
  → 在不修改 relaykit 公共 API 的前提下进行最小修复
```

协议转换核心本阶段仍不修改；后续先用回归矩阵确认具体失败路径，再进入 `relay/` 和协议适配代码的专项工作。

- 不删除任务插件、视频、Suno、Midjourney 和任务产物代理；
- 不删除 io.net、部署、多节点、节点状态和系统任务；

- 不删除普通图片、音频、Embedding、Rerank 和 Codex 渠道能力；
- 不修改 `relay/`、`relaykit/` 的转换器实现和公共转换 API；
- 不通过前端隐藏代替后端路由保护；
- 不为了删除支付而删除管理员额度、Token 额度、预扣、结算、退款和日志；
- 不修改项目名称、作者、版权、许可证和归属信息。
